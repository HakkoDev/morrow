# v0.2.0 desktop smoke tests

- Use two separate accounts. Send a message into only one; verify the new message appears via IMAP IDLE without leaking into the other account.
- Disable IDLE on a test server. Verify the 60-second polling fallback continues to update the Inbox.
- Disconnect and restore networking. Confirm exponential reconnection doesn't produce repeated new-mail notifications.
- Deny desktop notification permission, then opt in under Settings. Confirm notifications contain no sender or subject information and account muting works.
- Confirm tray Show/Quit controls after installation; verify Windows taskbar overlay (including 9+ and count clearing), Linux/macOS badge support when available, and unread count in the tooltip.
- Save a rich-text draft with underline, numbered list and inline PNG, close/reopen, and verify formatting plus a plain-text MIME alternative. Verify CID MIME attachments render in other clients; paste hostile HTML and verify it is not retained.
- Search Unified Inbox with `from:alice`, `in:INBOX`, and date operators; verify account-scoped results and SQL filter behavior.
- Back up and migrate schema v3, v4, and v5 databases to v6; confirm all old messages, OAuth account settings and drafts are intact.
- Run `bun run biome:check`, `bun run typecheck`, `bun run test:source`, `cargo fmt --all -- --check`, `cargo clippy` and `cargo test` before tagging.
- Upload a draft via **Sync draft** to a UIDPLUS-capable provider. Repeat the upload without editing and verify exactly one matching server copy; edit and re-upload, verify no old tagged copies remain. Disconnect immediately after APPEND, reconnect, retry and verify duplicates are not silently created. Make a local draft without a To address: it must be safely uploadable to IMAP without a fake To header, while SMTP sending still refuses empty recipients.
- On a UIDPLUS-less server, Sync draft must fail safely without deleting any unrelated \Deleted message. Verify remote drafts created by another client are never modified.
- Send a previously synchronized draft. Verify that only the tagged server-side copy is cleaned up, and a failure to clean up cannot make the already-sent SMTP mail appear failed.

## Two-way Drafts integration test matrix (required before release)

1. Start draft A on Morrow PC; wait for debounced upload. Confirm one Morrow-owned copy in IMAP Drafts. Open a second Morrow instance and verify the draft downloads automatically without leaking into another account.
2. Edit the draft on PC A while PC B is closed. Start PC B and verify the updated subject/body arrives. Repeat with a third-party IMAP client *that preserves Morrow UUID headers*; ensure the MIME content SHA detects its change even when the revision header was not updated.
3. Edit the same draft offline on PC A while the server version changes. Reconnect: confirm no automatic overwrite, a conflict status, and a separate recoverable server copy if MIME is supported. Test **Keep local** and **Use server** individually, verifying both old versions have backups.
4. Test a local draft with no recipients: confirm IMAP upload and recovery with no synthetic To header. Test remote rich-text draft with CID images or attachments: confirm that unsafe server-to-local import fails and no MIME bytes silently vanish.
5. Delete server draft, then reconnect: local recovery remains; the user can explicitly restore it. Delete local-only copy: it must not immediately re-import the same remote UUID. Send a draft: ensure only the exact last-synced UID is eligible for cleanup.
6. Force UIDVALIDITY change, IMAP UIDPLUS unavailable, more than 500 Drafts entries, and a network disconnect during APPEND. Verify no mailbox-wide EXPUNGE, no wrong-UID deletion, and no loss of unsent local work.
7. Test Morrow Drafts with Mailcow, Gmail and Microsoft IMAP. Generic drafts originating in Gmail/Outlook/Apple Mail are intentionally **not yet bidirectionally imported**; do not mark full cross-client compatibility complete.

### Phase 2 interoperability manual tests (must pass before release)

- [ ] **No recipient:** Create a draft with only a subject/body. Sync and verify the IMAP folder contains the draft with no synthetic `To:` header. Restart Morrow and restore it. Verify SMTP Send still refuses an empty `To` field.
- [ ] **Bcc:** Save a draft with a Bcc contact. Verify the exact recipient remains in the server Drafts MIME and after reopening in Morrow; verify ordinary sent mail does not expose the Bcc header.
- [ ] **External provider import:** Create a draft in Gmail, Outlook or Apple Mail, click **Find drafts** and **Import copy** in Morrow. Verify the local copy is editable, original server message stays unchanged, and imported copy gets its own UUID. Check that manually uploading the copy creates an independent provider draft.
- [ ] **Attachments:** Import a 2 MB PDF and an inline PNG, disconnect, restart, and verify both remain available and can be sent. Verify unsupported MIME is rejected with the original unchanged.
- [ ] **Security:** Replace a UIDVALIDITY while the import chooser is open and confirm import refuses stale selection; ensure Morrow-owned UUID messages aren't listed as foreign drafts and are not deleted during import.
- [ ] **Conflicts:** Edit a Morrow-owned draft from another client, then edit it offline in Morrow. Verify conflict resolution keeps local and server recovery copies; avoid sending multiple copies.
- [ ] **Native release:** Run `bun run deps:sync`, full `bun run check`, `cargo test --manifest-path src-tauri/Cargo.toml`, and install/smoke-test the Windows NSIS build. Check current Cargo.lock is regenerated.
