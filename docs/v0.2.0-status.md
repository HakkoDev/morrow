# v0.2.0 development status

This branch is a source candidate. Do not tag or publish it as a finished release until the checks below pass.

## Implemented in source

- Account-scoped cached unified Inbox, favorite folders, and cached unread counts.
- SQLite FTS5 incremental indexing and offline search with `from:`, `in:`, `after:YYYY-MM-DD` and `before:YYYY-MM-DD`. Unified Inbox searches across accounts; individual-folder searches retain their account and folder scope. Dates are UTC, `after:` includes that day, and `before:` excludes it. Invalid calendar dates return an error. Input is parameterized, not inserted into SQL.
- Thread relationships via Message-ID, References and In-Reply-To, with account-scoped navigation.
- Local SQLite drafts, autosave and recovery. The schema has been migrated to v4 to preserve HTML bodies.
- Basic rich-text formatting (bold, italic, bullet lists), plaintext fallbacks and restricted HTML. Pasted HTML is stripped to plaintext; sending builds a MIME multipart/alternative. **Inline images are not implemented.**
- IMAP IDLE watchers on supported servers, bounded sessions, exponential reconnect backoff, and the existing 60-second polling fallback. Only INBOX is watched using IDLE.
- Opt-in native notifications without sender/subject/body, account-specific mute controls, and a Windows/Linux tray menu with Show/Quit. Unread count is shown in the tray tooltip; a taskbar badge is not implemented.
- Existing sandboxed, sanitized email reading, remote-image blocking, and GPL-3.0-only licensing.

## Still blocked or incomplete

- **Gmail and Microsoft OAuth2:** A trustworthy desktop flow requires registered provider client IDs, consent/scopes, PKCE, refresh-token storage, and XOAUTH2 IMAP/SMTP. This source still uses account passwords/app passwords. Do not claim OAuth2 works.
- **Server Drafts sync:** Drafts are still saved locally. Robust remote replacement/recovery requires UID-scoped operations and per-server conflict handling; naive repeated APPEND would create duplicates.
- Inline image composition, multiple sender identities per account, full indexing-progress UI, and a taskbar unread badge.
- Live IMAP IDLE/fallback tests, Tauri notifications/permissions on installed Windows/Linux, production-sized mailboxes, and provider-specific validation.

## Verify before publishing

1. Back up your existing SQLite cache, especially before opening it with a schema-4 build. The database cannot be opened by an older binary afterwards.
2. Install dependencies with `bun install --frozen-lockfile` and run `bun run deps:check`. Both lockfiles have been refreshed, and the Rust notification plugin is pinned to match the JavaScript package. When deliberately changing dependencies, refresh and commit both locks.
3. Run `bun run biome:fix`, `bun run biome:check`, `bun run typecheck`, `bun run test:source`, `bun run build`.
4. Run `cargo fmt --manifest-path src-tauri/Cargo.toml --all`, `cargo test --manifest-path src-tauri/Cargo.toml`, and `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets`.
5. Build and smoke-test installed Windows NSIS and Linux AppImage/DEB binaries. The native notification plugin requires Rust 1.90 or newer.
6. Test two providers with IMAP IDLE on/off, network loss/reconnect, account deletion during IDLE, rapid account switching, notification permission denial and per-account mute, draft migration/recovery, and search isolation.
7. Verify signed updater metadata, platform assets, and LICENSE are present in the draft GitHub Release before publishing.

Source-contract and SQLite smoke checks are not substitutes for real Cargo, Biome, TypeScript, or live mail-provider tests.
