# Security Policy

Thank you for helping keep Morrow and its users safe.

## Supported versions

Security fixes are generally targeted at the latest released version. Older versions may not receive backported fixes. Check the repository's Releases page for the newest build.

## Reporting a vulnerability

**Do not open a public issue, discussion, or pull request containing vulnerability details.**

1. Open this repository's **Security** tab and select **Report a vulnerability** (GitHub Private Vulnerability Reporting), if enabled.
2. If that option is unavailable, contact the repository maintainers privately through a maintainer-approved contact method listed on the repository profile or project website. Do not include sensitive exploit details in a public message asking for contact instructions.
3. Include the affected version and operating system, impact, steps to reproduce, and a minimal proof of concept if safe to share. Explain any prerequisites and recommended mitigations.

Please avoid testing against other people's systems, accessing data you do not own, disrupting services, or publishing a proof of concept before a coordinated fix.

## What to expect

Maintainers will attempt to acknowledge actionable private reports, investigate, and coordinate remediation and disclosure as capacity permits. There is **no guaranteed response or patch timeline**, and this project does not operate a bug bounty program.

## In scope

Examples include exposure of mail account credentials, OAuth tokens, message contents, attachments, IMAP/SMTP connections, local databases, or updater signatures, privilege escalation, unsafe file operations, unexpected network access, malicious input processing, and release/update integrity issues.

For normal bugs, feature requests, installation issues, or general support questions, use the public issue templates instead. Please redact tokens, passwords, message contents, private URLs, and personal data from logs and screenshots.
